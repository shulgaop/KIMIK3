# CLAUDE.md — инструкции для Claude Code
# Проект: Генератор путеводителей горных походов (route_app)

Ты работаешь над приложением, которое по программе похода (PDF), GPX-треку и датам
генерирует комплект: MD-гид, офлайн HTML-гид, аудиогид (mp3), GPX/KML с точками,
ICS-календарь, чеклисты и файл-снимок СТАТУС.

## Источники истины (читай в первую очередь)
1. `../Инструкция_генерация_горных_маршрутов.md` — методика (структура гида, правила,
   типовые грабли, чек-лист выдачи). НЕ нарушать её правила без явной команды.
2. `ТЗ_приложение_генератор_горных_маршрутов.md` — что строим (MVP: F1–F6, F9).
3. `СТАТУС_<Маршрут>.md` эталонного проекта — формат снимка проекта.

## Жёсткие правила
- Все вычисления (километраж, набор/сброс, азимуты, градиенты) — ТОЛЬКО через
  `scripts/gpx_analyze.py` или его функции. Никогда не считать «на глаз».
- Градиенты — скользящим окном 300–500 м (см. скрипт). Точечные значения запрещены
  (GPS-шум даёт фантомные 50–65°).
- KML: координаты только `долгота,широта,высота`; ID стилей — латиница без пробелов;
  внешние иконки запрещены. После генерации обязателен запуск валидации
  (`scripts/make_kml.py` делает её сам: XML + bbox + styleUrl↔id).
- Погода: если даты дальше 10–14 дней — климат + дата перепроверки, прогноз не выдумывать.
  После дат похода — режим «фактические наблюдения» (для отчёта).
- Факты в гиде (высоты, даты, статусы ЮНЕСКО, числа) верифицировать; сомнительное
  помечать «по отзывам/по преданию».
- Имена выходных файлов — на языке пользователя (русском), без транслита и версий
  вроде `_v2_final`.
- ПОСЛЕ КАЖДОГО изменения файлов выдачи обновлять `СТАТУС_<Маршрут>.md`
  (структура — раздел 0 инструкции). Без этого задача не завершена.

## Структура репозитория
```
route_app/
  ТЗ_приложение_генератор_горных_маршрутов.md
  CLAUDE.md            # этот файл
  AGENTS.md            # зеркальные инструкции для Kimi Code
  scripts/
    gpx_analyze.py     # разбор GPX: км, высоты, проекции, азимуты, градиенты
    make_kml.py        # генерация KML по дням + жёсткая валидация
    make_ics.py        # календарь ICS (VTIMEZONE, VALARM)
    weather.py         # погодный движок F3: прогноз/климат/факт (Open-Meteo)
    make_status.py     # снимок проекта СТАТУС_<Маршрут>.md (F9, после каждого изменения выдачи)
    make_checklist.py  # интерактивный чеклист HTML (F8: Web Speech API, localStorage, печать)
    tts_audioguide.py  # edge-tts: тексты с числами прописью → mp3 + ffprobe
  routegen/            # (создаётся) Python-пакет приложения
  projects/<маршрут>/  # входные и выходные файлы конкретного похода
```

## Команды
- Разбор трека:        `python3 scripts/gpx_analyze.py track.gpx --points points.json`
- Генерация KML:       `python3 scripts/make_kml.py track.gpx out.kml --bbox 38.9 39.6 67.9 68.5`
- Календарь:           `python3 scripts/make_ics.py events.json out.ics`
- Погода (F3):         `python3 scripts/weather.py points.json --start 2026-09-06 --end 2026-09-16`
- Снимок проекта (F9): `python3 scripts/make_status.py projects/Фанские_горы`
- Чеклист (F8):        `python3 scripts/make_checklist.py checklist.json Чеклист.html`
- Аудиогид:            `python3 scripts/tts_audioguide.py texts.json out_dir/ --voice ru-RU-DmitryNeural`
- Тесты (когда будут): `python3 -m pytest routegen/tests -q`

## Поток работы над фичей
1. Прочитай ТЗ и инструкцию, найди затрагиваемые разделы.
2. Пиши код в `routegen/`, переиспользуй функции из `scripts/`.
3. Прогони на эталоне (Фаны): GPX → отчёт анализа; сравни с эталонными числами
   (Чимтарга 4740 м, ~60 км, уклоны осыпных взлётов 30–40°).
4. Обнови СТАТУС проекта и опиши изменение в ответе.

## Git-процесс (постоянное правило)
- Каждый проверенный блок — атомарный «зелёный» коммит и сразу `git push origin main`.
- Готовые изменения локально не копим: незакоммиченные блоки проверяем и коммитим
  отдельными атомарными коммитами с push в той же сессии.
- Перед коммитом — прогон затронутых скриптов на эталоне Фанов (без traceback,
  вывод правдоподобен); `weather.py` — во всех применимых режимах; изменённые
  страницы `app/` — открыть в браузере офлайн.
- Коммит на русском, одна строка: что изменено. Без push задача не завершена.
