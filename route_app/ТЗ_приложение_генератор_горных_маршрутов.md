# ТЗ: Приложение «Генератор путеводителей горных походов»

*Черновик ТЗ. Версия 0.1 (27.09.2026). Основано на методике `Инструкция_генерация_горных_маршрутов.md` и эталонном проекте «Фанские горы — кольцо Чимтарги».*

## 1. Назначение
Веб-приложение, которое по входным данным похода (программа PDF, GPX-трек, билеты, даты) автоматически производит полный комплект документов горного похода:
1. MD-путеводитель (структура раздела 4 инструкции);
2. офлайн HTML-гид (один самодостаточный файл, печать, мобильный);
3. аудиогид (mp3, TTS, числа прописью, привязка треков к точкам);
4. GPX с точками аудиогида + KML для Google Earth;
5. ICS-календарь (дни маршрута, билеты, отели) для импорта в Google Календарь;
6. интерактивные чеклисты (HTML, озвучка через Web Speech API, localStorage);
7. файл-снимок `СТАТУС_<Маршрут>.md` для продолжения работы в любой модели.

## 2. Пользователи и сценарии
- **Руководитель похода**: загружает программу и GPX → получает комплект → правит через чат-итерации («обнови погоду», «отель поменялся») → экспортирует.
- **Участник**: открывает HTML-гид и чеклисты по ссылке, слушает аудиогид офлайн.

## 3. Функциональные требования (ядро)
| № | Функция | Описание | Приоритет |
|---|---|---|---|
| F1 | Импорт входных | PDF-программа (извлечение дат/дней/ночёвок/рейсов), GPX, билеты. Реализовано: `scripts/read_program.py` (PDF/DOCX/TXT → текст + черновик точек эвристиками; смысловой разбор — LLM-агент) | MUST |
| F2 | Анализ GPX | километраж (гаверсинус), высоты, проекция точек программы на трек, набор/сброс по дням, азимуты плеч, градиенты окном 300–500 м | MUST |
| F3 | Погодный движок | до 10–14 дней — реальный прогноз (meteoblue/аналог API); дальше — климат + дата перепроверки; пересчёт на высоты градиентом −0,6 °C/100 м; после похода — фактические наблюдения для отчёта | MUST |
| F4 | Генерация гида (LLM) | разделы по структуре инструкции: логистика, погода/ветер, тропы, навигация, дни с факт-блоками, точки, опасности, снаряжение, геология/история/природа. Реализовано: `scripts/llm.py` (OpenRouter: бесплатные «:free» по умолчанию, платные — по ключу пользователя; контекст = файлы проекта + learn/) | MUST |
| F5 | Экспорт KML | дни разными цветами, placemarks по категориям; жёсткая валидация: lon,lat-порядок + bbox, латинские ID стилей, без внешних иконок | MUST |
| F6 | TTS-аудиогид | edge-tts (голос настраиваемый), тексты с числами прописью, 40–80 с/трек, ffprobe-проверка, zip; точки 🎧 в GPX | MUST |
| F7 | ICS-календарь | события с VTIMEZONE (пояса из маршрута), VALARM, экранирование запятых | SHOULD |
| F8 | Чеклисты | HTML с Web Speech API (озвучка неотмеченных), localStorage, печать. Реализовано: `scripts/make_checklist.py` | SHOULD |
| F9 | Снимок проекта | автообновление `СТАТУС_<Маршрут>.md` после каждого изменения выдачи. Реализовано: `scripts/make_status.py` | MUST |
| F10 | Валюта/логистика | курсы ЦБ стран маршрута на дату запроса; блок «деньги» | SHOULD |
| F11 | Режим отчёта | после дат похода: замена прогноза на факт-наблюдения, блок «прогноз vs факт» | COULD |

## 4. Нефункциональные требования
- Выходные файлы — на языке пользователя, имена файлов человекочитаемые.
- HTML-гид: ноль внешних зависимостей (инлайн CSS/JS, системные шрифты, кириллица), печать A4, мобильная вёрстка.
- Все вычисления (км, азимуты, градиенты) — только скриптами, никогда «на глаз» (см. `scripts/gpx_analyze.py`).
- Факты в гиде — верифицируемые; сомнительное помечается «по отзывам/по преданию».
- Хранение проектов: папка проекта со всеми входными и выходными файлами + СТАТУС.

## 5. Архитектура (предложение)
- **CLI/агентный контур**: Python-пакет `routegen` + скрипты из `scripts/`; оркестрация LLM-агентом (Claude Code / Kimi Code) по `CLAUDE.md`/`AGENTS.md`.
- **Веб-контур (v2)**: FastAPI backend (загрузка файлов, задачи генерации, хранение проектов в SQLite/Postgres), React-фронтенд (мастер входных данных → прогресс → предпросмотр HTML-гида в iframe → экспорт zip). MVP-интерфейс уже реализован: `webapp.py` + `wizard.html` (FastAPI, одностраничный мастер + вкладка «Обучение», проекты в `projects/<маршрут>/`, zip-экспорт).
- **LLM-слой**: промпт-пакеты по разделам инструкции; каждая итерация правит файлы проекта и обновляет СТАТУС.

## 6. Этапы
1. **MVP (CLI)**: F1–F6, F9 на скриптах + агентные инструкции. Приёмка: полный комплект по новому маршруту за один прогон.
2. **v1.1**: F7, F8, F10 + регрессионные тесты на эталоне Фанов.
3. **v2 (web)**: FastAPI + фронтенд, очередь задач, превью, многопользовательность.

## 7. Приёмочные критерии MVP (чек-лист из раздела 10 инструкции)
- Все ночёвки и перевалы программы найдены в GPX; км и высоты посчитаны скриптом.
- Градиенты окном 300–500 м; таблица «тропа/уклон/сложность» заполнена.
- KML проходит: XML валиден, все координаты в bbox региона, styleUrl↔id совпадают.
- Аудиогид: числа прописью, ffprobe 40–80 с, zip.
- HTML открывается офлайн в Edge; печать чистая.
- СТАТУС обновлён автоматически.
