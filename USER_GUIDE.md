# USER_GUIDE.md — как пользоваться мастером генерации маршрутов

Мастер — локальный веб-интерфейс (`route_app/webapp.py`), который запускает
скрипты проекта в правильном порядке и собирает результат в папку проекта.
Установка — в **INSTALL.md**. Запуск: `python3 webapp.py` → http://127.0.0.1:8077

## Понятия

- **Проект** = один поход. Хранится в `route_app/projects/<название>/`:
  - `входные/` — то, что вы загрузили (`track.gpx`, `points.json`, …);
  - `выходные/` — всё, что сгенерировано;
  - `СТАТУС_<название>.md` — снимок проекта, обновляется автоматически
    после каждого шага (по нему любой AI-агент продолжит работу).
- **Обучение** — правила генерации и база эталонных примеров, которые
  AI-агент подмешивает в промпты при генерации гида и аудиотекстов.

## Мастер: шаг за шагом

### 1 · Проект
Введите название маршрута (можно по-русски), даты начала и конца похода,
нажмите **«Создать проект»**. Существующий проект открывается из списка.

### 2 · Программа и точки
- **Описание маршрута** — PDF, DOCX или TXT в свободной форме: загрузите файл
  или вставьте текст в поле. Старый бинарный .doc не читается — пересохраните
  как .docx. Скан без текстового слоя не поддерживается (нужен OCR).
- Кнопка **«Прочитать и извлечь точки»**: приложение извлекает текст
  (`входные/программа.txt`) и готовит **черновик** точек по высотам
  (…м) и координатам, находит даты и дни. Черновик подставляется в редактор
  points.json — **проверьте и дополните его** (эвристика не заменяет смысловой
  разбор), затем нажмите «Сохранить points.json». Если в тексте есть даты
  с годом — даты проекта подставятся в шаг 1 автоматически.
- **track.gpx** — трек маршрута (выгрузка из Organic Maps/планировщика).

Извлечённый текст программы (`входные/программа.txt`) — вход для всех
модулей: гида (F4), отчёта, аудиогида; AI-агент читает его при генерации.

### 3 · Анализ трека
Кнопка **«Запустить анализ»**: километраж, высоты, проекция точек на трек,
плечи между точками, максимальные уклоны скользящим окном 400 м.
Результат — `выходные/анализ.json` + сводка на экране.

### 4 · Погода
Кнопка **«Собрать погоду»** (используются даты из шага 1). Режим выбирается
автоматически:
- до похода ≤ 14 дней — реальный прогноз;
- раньше — климатические нормы за 10 лет + **дата перепроверки**;
- после похода — факт (реанализ ERA5) для отчёта «прогноз vs факт».

Температуры пересчитываются на высоту каждой точки (−0,6 °C/100 м).
Результат — `выходные/погода.json` и готовый блок `выходные/Погода.md`.

### 5 · Гид (ИИ, OpenRouter)
Генерация MD-путеводителя из данных проекта (программа + анализ + погода +
правила и примеры из «Обучения»). Нужен ключ OpenRouter — бесплатный,
берётся на https://openrouter.ai/keys за минуту.
- **Бесплатные модели** — в выпадающем списке (список живой, обновляется с
  OpenRouter; по умолчанию выбрана самая сильная доступная).
- **Платные модели** — если у вас платная подписка/баланс OpenRouter, впишите
  id модели в поле ниже (например `openai/gpt-5`, `anthropic/claude-sonnet-4`)
  — спишется с вашего аккаунта OpenRouter.

Ключ хранится локально в `learn/llm_config.json` (в git не попадает).
Результат — `выходные/Гид.md`.

Сопутствующие кнопки этого шага:
- **HTML-версия гида** — `выходные/Гид.html`: офлайн-страница с оглавлением,
  SVG-профилем высот из track.gpx и отметками точек, печатью A4;
- **Тексты аудиогида (ИИ)** — `выходные/аудиотексты.json`: 8–14 треков,
  все числа прописью, 110–190 слов на трек (проверяется автоматически);
- **Озвучить mp3** — edge-tts (голос ru-RU-DmitryNeural) →
  `выходные/Аудиогид/*.mp3` + `Аудиогид.zip`. Нужен `pip install edge-tts`;
  для проверки длительности треков установите ffmpeg (ffprobe).

### 6 · Документы
- **KML для Google Earth** — дни разными цветами; при желании укажите границы
  дней по километражу (например `8 16 24`). Точки из points.json добавляются
  как метки. Валидация (bbox, стили) — автоматически.
- **Календарь .ics** — отредактируйте `события.json` (подставлен шаблон из
  дат проекта), сохраните, нажмите «Сделать календарь». Файл импортируется
  в Google Календарь.
- **Чеклист.html** — отредактируйте `чеклист.json` (разделы и пункты),
  сохраните, нажмите «Сделать Чеклист.html». Получится офлайн-чеклист
  с озвучкой неотмеченных пунктов (голос браузера) и сохранением отметок.

### 7 · Фотографии и видео
Нажмите **«📁 Выбрать папку с фото…»** — откроется проводник по папкам
компьютера (видно, сколько фото/видео в каждой папке). Затем одна большая
кнопка **«Обработать фото: сортировка + фотометки + отчёт»** выполняет всё:
1. **Сортировка по точкам и дням** → `выходные/фото/День_N_точка/…`,
   офлайн `фотоотчёт.html`, манифест `фото_карта.json`;
2. **Фотометки к аудиогиду** → `фотометки.kml` (превью фото в Google Earth,
   папки по трекам 🎧) + `фотометки.json`;
3. **Отчёт с картой** (hike_report) → `карта_похода.html`, `отчёт_похода.xlsx`,
   `файлы_без_геометок.txt` — прямо в папке с фото. Работает с видео и
   DJI-телеметрией. Из мастера карта строится без скачивания офлайн-тайлов
   (быстро); полный офлайн-вариант с тайлами: `python3 scripts/hike_report.py
   <папка>` вручную. Нужны зависимости: `pip install folium openpyxl
   reverse-geocoder pyosmogps` — без них подшаг честно пропускается.

Каждый подшаг терпим к отсутствию входных: чего-то не хватает — он пропускается
с пояснением, остальное выполняется.

Как привязываются фото:
- у фото есть EXIF-GPS → ближайшая точка маршрута (дальше 1 км — «Мимо маршрута»);
- GPS нет, но есть время съёмки и в track.gpx есть таймстемпы → позиция
  интерполируется на треке по времени;
- без EXIF — группа «Неразобранное» (ничего не выдумывается).

### 8 · Результат
Список файлов выдачи со ссылками на скачивание + **«Скачать всё (zip)»** —
весь проект одним архивом (входные, выходные, СТАТУС).

## Обучение (вкладка «Обучение»)

- **Правила генерации** — короткие проверяемые правила («числа в аудиотекстах
  прописью», «уклоны — только из таблицы анализа»). Хранятся в
  `route_app/learn/правила.md`.
- **База примеров** — эталонные пары «вход → фрагмент выдачи» (few-shot):
  как должен выглядеть день маршрута, аудиотекст, блок опасностей.
  Хранятся в `route_app/learn/примеры.json`.

AI-агент (Kimi Code / Claude) читает оба файла перед генерацией гида (F4):
правила — как ограничения, примеры — как образцы стиля. Чем точнее примеры,
тем стабильнее выдача. Удаление примера — кнопкой ✕.

## Эквиваленты в командной строке

Всё, что делает мастер, можно запустить вручную из `route_app/`:

| Шаг мастера | Команда |
|---|---|
| Программа | `python3 scripts/read_program.py программа.docx --out-points points_draft.json` |
| Анализ | `python3 scripts/gpx_analyze.py track.gpx --points points.json` |
| Погода | `python3 scripts/weather.py points.json --start ГГГГ-ММ-ДД --end ГГГГ-ММ-ДД --md Погода.md` |
| Гид (ИИ) | `python3 scripts/llm.py guide projects/<маршрут>` (ключ: OPENROUTER_API_KEY) |
| Модели | `python3 scripts/llm.py models` — список бесплатных моделей OpenRouter |
| KML | `python3 scripts/make_kml.py track.gpx out.kml --bbox S N W E` |
| Календарь | `python3 scripts/make_ics.py события.json календарь.ics` |
| Чеклист | `python3 scripts/make_checklist.py чеклист.json Чеклист.html` |
| Фото | `python3 scripts/photo_sort.py /папка/фото --points points.json --start ГГГГ-ММ-ДД --out выходные/` |
| Фотометки | `python3 scripts/photo_marks.py /папка/фото --gpx track.gpx --out выходные/` |
| СТАТУС | `python3 scripts/make_status.py projects/<маршрут>` |

## Хорошие практики

- После любых ручных правок файлов проекта нажмите шаг «Документы» →
  любой генератор или выполните `make_status.py` — СТАТУС должен быть свежим.
- Даты похода ближе 14 дней? Перезапустите шаг «Погода» — появится настоящий
  прогноз вместо климата.
- Перед походом скачайте zip и держите копию в телефоне: HTML-гид и чеклист
  работают офлайн.
